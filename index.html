Самый быстрый движок для Qwen3.8-Flash-Next на xeon (2×RTX 5090)

Отчёт от 12 ноября 2026 г. Все скорости взяты из опубликованных источников (Basalt docs / community benchmarks, GitHub, Hugging Face, vLLM recipes, обзоры). На этой машине ничего не замерялось; аппаратная часть собрана командами nvidia-smi, lscpu, free, df 12.11.2026.

Вывод: движок — Basalt (форк Strata), он уже стоит и работает. Ни один «универсальный» движок не даёт на этом железе ничего близкого: 461 tok/s против 40–180 tok/s у llama.cpp / Strata на одной карте; vLLM и SGLang для 64 ГБ VRAM официально не поддерживают модель. Реальный выбор — не движок, а топология PCIe второй карты и квант внутри Basalt: вместе это ~550–600 tok/s вместо текущих 461.

2. Модель

Qwen/Qwen3.8-Flash-Next, архитектура Qwen4ExpForConditionalGeneration (model_type: qwen4_exp):

  • 125 млрд параметров основной модели + 51 млрд N-gram/PLE-таблица + 4 млрд MTP-модуль; активируется ~6 млрд на токен (10 экспертов из 512, moe_intermediate_size: 640).
  • 48 слоёв, full_attention_interval: 4 — три из четырёх слоёв Gated DeltaNet (линейное внимание), каждый четвёртый — Qwen Sparse Attention; 24 головы, 2 KV-головы, head_dim: 256.
  • Мультимодальность (vision-энкодер, 27 слоёв), контекст 262 144 нативно (1M через YaRN).
  • Размеры чекпойнтов: BF16 — 360 000 192 888 Б (335.28 ГиБ), FP8 — 185 523 317 458 Б (172.78 ГиБ).

Практический смысл: «6B активных» не означает маленьких требований к памяти — эксперты и PLE-таблица должны где-то лежать, поэтому движки делятся на «для датацентра (4–8 карт по 141–288 ГБ)» и «со стримингом экспертов по RAM/SSD» (Strata, Basalt, llama.cpp).

5. Где на этой машине реальная скорость (по источникам)

  1. Вторая 5090 на PCIe 4.0 ×4 — главный рычаг. Движок прайсит prompt split и layer split «из each card's memory bandwidth, the probed link rates» и отключает часть механизмов на медленной паре карт; две одинаковые карты (5090+5090 = «alike», ±10 % по пропускной способности и VRAM) дополнительно получают layer split с перекрытием окон и раздел GDN между картами (docs/configuration/gpus.md). Ориентир: 461 → 553 tok/s на связке ×8+×8 со слабым CPU, то есть порядка +20 % за перестановку карты в полноценный ×8/×16 слот.

  3. Ваш NVFP4-пак — не текущий DQ6_K. Лежит Qwen3.8-FN-NVFP4.basalt (123.2 ГБ), в репозитории сейчас Qwen3.8-FN-NVFP4-DQ6_K.basalt (131.7 ГБ). 6-битные dense-проекции вместо 8-битных дают документированные +5.6…+10.2 % decode (prose 213.4 → 229.9, conversation 251.0 → 265.1, structured 420.4 → 463.5) и меньший KLD, чем у DQ8.
  4. Флаги, которые касаются ваших конфигов: --spec 3 при дефолте 8 (окно MTP-черновика); --kv int8 документально lossless (ΔKLD +0.0000), а k8v4 (+0.0056) и q4_0 (+0.0093) уже «measurable» — дальше int8 идти не стоит; --prefill auto для NVFP4 читает чанками до 32 768 токенов, доля CPU --prefill-cpu-share 0.6 на качество не влияет (ΔKLD +0.0025 в пределах шума); FP4-тензорные ядра вместо MMQ ускоряют prefill на 17–19 % (64K: 8 201 против 10 126 tok/s).
  5. Лимит питания: 500 Вт из 575 доступных на обеих картах. В тех же рядах при 575 Вт против 489 Вт: IQ3_S 486.7 против 431.1 (+12.9 %).

Ожидаемый эффект от пунктов 1–3: ~550–600 tok/s в холодном community-бенчмарке вместо 461. В длинных агентских сессиях на 262K (по вашему UPDATE.md — 70–103 tok/s) прирост заметно меньше: там доминируют объём контекста и elastic KV, а не пропускная способность экспертов.

6. Когда Basalt не оптимум

  • Нужен вариант модели, для которого есть только GGUF (например, Qwen3.8-Flash-Next-AtomicChat, который у вас лежит, или сторонние abliterated-сборки) → llama.cpp build 12292 из /neuro/llamacpp с --n-cpu-moe / --override-tensor и --spec-type draft-mtp; ожидайте 40–80 tok/s, а не 400.
  • Следить за vLLM #64952 (pipeline parallel для Qwen4Exp) и RFC «Incremental MoE Expert Offloading — GPU Cache + Async Pipeline»: если допилят до consumer-карт, расклад изменится. На сегодня это 4–8 карт по 141–288 ГБ.
  • Strata (апстрим) — если понадобится экосистема GGUF-паков и обходные пути (AMD/Arc/Mac), но на 2×5090 Basalt является его Blackwell-форком: +13 % decode в 0.2.0 (prose 297 → ~330–337) и более свежие правки decode в 0.3.x.
